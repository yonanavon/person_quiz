# מפרט טכני: תחנות משחק "אתגרי חשיבה"

מסמך זה מחייב כל סוכן שבונה תחנה. הרקע המלא: `docs/cognitive-games-plan.md`.

## עקרון-על: עצמאות מוחלטת

כל תחנה היא **קובץ HTML אחד עצמאי** ב-`public/games/<slug>.html` — כל ה-CSS וה-JS בתוכו (inline). אסור:
- לערוך קבצים קיימים כלשהם (`server.js`, `db.js`, `public/index.html`, `public/games/index.html`, קבצי תחנות אחרות וכו')
- להוסיף תלויות npm או קבצים משותפים
- להסתמך על תחנה אחרת או על קוד שלה

התשתית היחידה שמותר להשתמש בה (כבר קיימת, לא לגעת בה):
- `POST /api/games/result` — שמירת תוצאה. גוף הבקשה:
  ```json
  {
    "name": "שם התלמיד",
    "classCode": "קוד כיתה (אופציונלי)",
    "station": "<slug>",
    "metrics": { ...מדדי התחנה... },
    "reliability": { "flags": ["..."], "practicePassed": true },
    "durationSeconds": 123
  }
  ```
- דף הבית `public/games/index.html` כבר מקשר ל-`<slug>.html` — אין צורך לעדכן אותו.

## קהל היעד וכללי תוכן

- בנים, כיתות ז'-ח', ציבור חרדי. עברית פשוטה וברורה, RTL מלא.
- תוכן ניטרלי בלבד: צורות גאומטריות, מספרים, צבעים. בלי דמויות, בלי מוזיקה. צלילי משוב קצרים (WebAudio) — אופציונלי בלבד ועם כפתור השתקה.
- טון מעודד ומשחקי. בסיום — משוב חיובי כללי ("כל הכבוד! הגעת לשלב X") בלי ציונים, בלי אחוזונים, בלי השוואה לאחרים. הפרשנות שמורה למורה בלבד.

## מבנה חובה של כל תחנה (מסכים)

1. **מסך פתיחה**: שם התחנה + הסבר קצר במילים פשוטות + טופס שם וקוד כיתה. אם הגיעו `?name=...&class=...` ב-query string — למלא מראש ולדלג על הטופס (להציג "שלום <שם>"). קוד כיתה אופציונלי.
2. **תרגול**: לפחות 2-3 סבבי תרגול עם משוב מיידי (נכון/טעות והסבר). התרגול לא נספר בציון. אם התלמיד נכשל בכל התרגול — לאפשר לחזור על ההסבר ולתרגל שוב (עד פעמיים), ולסמן זאת ב-reliability.
3. **המשחק עצמו**: לפי מפרט התחנה למטה. בלי משוב נכון/טעות במהלכו (אלא אם המפרט אומר אחרת).
4. **מסך סיום**: משוב מעודד + שליחת התוצאה ל-`POST /api/games/result`. אם השליחה נכשלת (שרת לא זמין) — עדיין להציג את מסך הסיום, לשמור את התוצאה ב-`localStorage` (מפתח `game-result-<slug>`) ולציין "התוצאה תישלח כשיהיה חיבור" עם כפתור "נסה שוב". קישור חזרה: `index.html` (לשמר את ה-query string).

## דרישות טכניות

- תמיכה מלאה בעכבר **ובמגע** (טאבלט). מטרות לחיצה גדולות (מינימום 48px).
- מדידת זמני תגובה ב-`performance.now()`.
- מניעת לחיצות כפולות, מניעת בחירת טקסט בזמן משחק (`user-select: none`).
- עיצוב נקי התואם את רוח האפליקציה הקיימת (רקע בהיר #f0f4f8, כרטיסים לבנים מעוגלים, פונט Segoe UI). אין לטעון קבצים חיצוניים — הכול inline.
- הקובץ חייב לעבוד גם בפתיחה ישירה בדפדפן (file://) — למעט שליחת התוצאה לשרת.

## דגלי מהימנות (reliability.flags)

כל תחנה מסמנת לפי הרלוונטי לה: `"random-pattern"` (דפוס תגובות אקראי), `"too-fast"` (זמני תגובה לא אנושיים, <150ms באופן עקבי), `"practice-repeated"` (חזר על תרגול), `"incomplete"` (נטש באמצע — אם נשמר משהו), `"low-effort"` (ראה מפרט תחנה).

## מפרטי התחנות

### 1. `corsi` — זיכרון הקוביות (Corsi Block-Tapping)
- 9 ריבועים בפריסה קבועה א-סימטרית (הפריסה הקלאסית של Corsi, מותאמת למסך). הריבועים נדלקים ברצף (600ms דלוק, 250ms כבוי בין ריבועים), ואז התלמיד לוחץ עליהם באותו סדר.
- מתחילים מרצף באורך 2. שני ניסיונות בכל אורך; אם לפחות אחד הצליח — עולים באורך. שני כישלונות באותו אורך — סוף המשחק. מקסימום אורך 9.
- תרגול: רצף באורך 2, עם הדגמה ויזואלית.
- metrics: `{ "span": <האורך המקסימלי שהצליח>, "totalCorrect": <מספר רצפים נכונים>, "trials": [{len, correct, timeMs}...] }`

### 2. `digit-span` — מספרים הפוכים (Digit Span לאחור)
- ספרות מוצגות על המסך אחת-אחת (ספרה גדולה במרכז, 1000ms הצגה + 300ms הפסקה). בסיום הרצף התלמיד מקליד את הספרות **בסדר הפוך** במקלדת מספרים גדולה על המסך.
- שלב חימום קצר: 2 רצפים קדימה (לא נספר). המשחק: לאחור, מתחיל מאורך 2, שני ניסיונות לכל אורך, עצירה אחרי שני כישלונות באותו אורך. מקסימום 8.
- אין שימוש באותה ספרה פעמיים ברצף אחד.
- metrics: `{ "backwardSpan": <אורך מקסימלי>, "totalCorrect": <רצפים נכונים>, "trials": [{len, correct}...] }`

### 3. `symbol-speed` — מהיר וממוקד (Symbol-Digit Coding)
- מפתח קבוע בראש המסך: 6 סמלים גאומטריים פשוטים (SVG inline) ↔ ספרות 1-6. במרכז מופיע סמל, והתלמיד לוחץ על הספרה המתאימה (כפתורים 1-6 גדולים בתחתית).
- 90 שניות עם שעון נראה. אחרי כל תשובה מופיע מיד סמל חדש (אקראי, לא אותו סמל פעמיים ברצף).
- תרגול: 5 תשובות עם משוב.
- metrics: `{ "attempted": n, "correct": n, "accuracy": 0-1, "meanRtMs": n, "correctPerMinute": n }`
- דגל `low-effort` אם accuracy < 0.5 (לוחץ אקראית).

### 4. `go-no-go` — עצור וסע (Go/No-Go)
- גירויים מופיעים במרכז: עיגול ירוק = ללחוץ מהר (על המסך כולו או מקש רווח), עיגול אדום = לא ללחוץ. 75% ירוק, 25% אדום, סדר אקראי (בלי יותר מ-2 אדומים ברצף).
- 60 גירויים: כל גירוי מוצג 650ms, ואז הפסקה אקראית 900-1400ms. סה"כ כ-2 דקות. הפסקה קצרה של 5 שניות באמצע.
- תרגול: 8 גירויים עם משוב.
- metrics: `{ "goTrials": n, "noGoTrials": n, "commissionErrors": <לחיצות על אדום>, "omissionErrors": <פספוסי ירוק>, "meanRtMs": n, "rtSdMs": n }`
- דגלים: `too-fast` אם RT חציוני <150ms; `random-pattern` אם commission errors > 50%.

### 5. `matrix` — חידות צורות (Matrix Reasoning)
- 12 פריטים בסדר קושי עולה. כל פריט: מטריצה 3×3 של צורות SVG שנוצרות פרוצדורלית לפי חוקים (השלמת שורה, התקדמות בגודל/מספר/סיבוב, שילוב שני חוקים), התא האחרון ריק, ו-5 אפשרויות תשובה (אחת נכונה + 4 מסיחים שנגזרים מהחוקים).
- הפריטים קבועים (seed קבוע) כדי שכל התלמידים יקבלו אותם פריטים.
- ללא מגבלת זמן לפריט, אך שעון כולל רך: אחרי 7 דקות מוצעת הצעה לסיים. אפשר לדלג על פריט (נחשב טעות).
- תרגול: פריט אחד קל מאוד עם הסבר של ההיגיון.
- metrics: `{ "items": 12, "correct": n, "skipped": n, "perItem": [{correct, rtMs}...], "totalTimeMs": n }`
- דגל `low-effort` אם זמן חציוני לפריט < 2 שניות.

## בדיקות חובה לפני סיום (של הסוכן הבונה)

1. `node --check` לא רלוונטי ל-HTML — במקום זה: לוודא שאין שגיאות תחביר ב-JS (אפשר לחלץ את ה-script לקובץ זמני ב-scratchpad ולהריץ עליו `node --check`).
2. להריץ את השרת (`node server.js`, SQLite מקומי), לוודא שהדף נטען (`curl http://localhost:3000/games/<slug>.html` מחזיר 200) ושה-POST עובד (לשלוח תוצאה לדוגמה ב-curl ולקבל `{"ok":true}`).
3. לכבות את השרת בסיום הבדיקה.
4. לסמלץ לוגיקה מרכזית ב-node אם אפשר (למשל: פונקציית יצירת רצפים, אלגוריתם הפריטים ב-matrix) ולוודא נכונות.
